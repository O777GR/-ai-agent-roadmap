# 📚 Источники вдохновения и референсы

Этот проект вдохновлён работами замечательных разработчиков, исследовательских групп и внутренними архитектурными находками. Ниже приведены репозитории, концепции и статьи, которые легли в основу архитектуры AI Agent Hub.

## 🏗️ Архитектура и песочницы

### **Mirage** — Виртуальный терминал для AI-агентов
🔗 [strukto-ai/mirage](https://github.com/strukto-ai/mirage)
- **Что взяли:** Архитектура виртуальной файловой системы (VFS), изолированных сред выполнения и детального контроля доступа.
- **Наша реализация:** `SandboxManager` с двухуровневой защитой (жёсткая граница `D:\Workspaces` + доверенные пути), аудит-лог `audit_log.jsonl`.

### **Sandbase Harness** — Эталонный локальный рантайм
🔗 [sandbase-ai/sandbase-harness](https://github.com/sandbase-ai/sandbase-harness)
- **Что взяли:** Концепция изоляции инструментов, управления сессиями и строгого логирования действий.

### **BitFun** — Изолированные мини-приложения
🔗 [GCWing/BitFun](https://github.com/GCWing/BitFun)
- **Что взяли:** Идея запуска задач агента как изолированных процессов с чёткими границами ресурсов.

## 🧠 Память, RAG и управление контекстом

### **ReMe** — Саморазвивающаяся база знаний
🔗 [agentscope-ai/ReMe](https://github.com/agentscope-ai/ReMe)
- **Что взяли:** Концепция локальной, эволюционирующей персональной базы знаний для агентов.
- **Наша реализация:** Модули `agent_memory.py` и проект WeKnora.

### **Ouroboros** — Агентная ОС для самосовершенствования
🔗 [Q00/ouroboros](https://github.com/Q00/ouroboros)
- **Что взяли:** Цикл "выполни → проанализируй ошибку (`stderr`) → сохрани решение → повтори".
- **Наша реализация:** Ouroboros Loop (автоматический перехват ошибок, анализ и сохранение уроков в `.ouroboros/lessons.md`).

### **MindMemOS** — Управление контекстом
🔗 [mindscale-noah/MindMemOS](https://github.com/mindscale-noah/MindMemOS)
- **Что взяли:** Автоматическая отработка навыков и интеграция с файловыми системами знаний.

### 🆕 **Best Practices for RAG Chunking** (Структурное разбиение)
🔗 [AI Manual: Настройка chunk size и overlap](https://ai-manual.ru/article/kak-podobrat-chunk-size-i-overlap-dlya-rag-nastrojka-na-svoej-dokumentatsii/)
- **Что взяли:** Критически важная концепция: код и таблицы нельзя резать по символам. 
- **Наша реализация:** Планируемый AST-парсинг для Python-кода (разбиение по функциям/классам) и рекурсивное разбиение Markdown по заголовкам для WeKnora/OpenViking.

### 🆕 **Zeal / Dash Docsets** — Оффлайн-справочник API
🔗 [zealdocs/zeal](https://github.com/zealdocs/zeal)
- **Что взяли:** Использование локальной SQLite базы данных (файл `.dsidx` или `.db`) внутри распакованных docset-ов для мгновенного, 100% оффлайн поиска точных имен функций, классов и сигнатур.
- **Наша реализация:** Планируемый MCP-инструмент `query_zeal_docs`, который полностью исключает галлюцинации модели при написании кода (особенно критично для .NET, Python, PyQt5), работая за миллисекунды без интернета.

## ⚡ Оптимизация локальных LLM

### 🆕 **OpenCode Cache Compact** (Сохранение префилл-кэша)
🔗 [AI Manual: Плагин cache-compact](https://ai-manual.ru/article/plagin-cache-compact-dlya-opencode-kak-uskorit-kompaktifikatsiyu-konteksta-na-lokalnyih-llm/)
- **Что взяли:** Понимание того, что изменение начала промпта (системных инструкций) полностью инвалидирует префилл-кэш в `llama.cpp`, вызывая огромные задержки.
- **Наша реализация:** Архитектурное правило: при сжатии контекста сначала генерируется саммари на полном диалоге, и только затем история заменяется на `[System] + [Summary] + [Recent]`, сохраняя префикс нетронутым до конца операции.

### 🆕 **Swift / Qwen Optimization** (Штраф за переосмысление)
🔗 [AI Manual: Swift Qwen 38-27B](https://ai-manual.ru/article/swift-qwen-38-27b-ot-ukisai-kak-shtraf-za-pereosmyislenie-uskoril-model-pochti-vdvoe/)
- **Что взяли:** Использование `repetition_penalty` и строгих негативных промптов для подавления избыточных "размышлений" (Chain-of-Thought) в рутинных задачах, что ускоряет инференс в разы.

### 🆕 **JEV (Joint Embedding-Vocabulary)**
🔗 [TypeSafe AI JEV](https://ai-manual.ru/article/jev-ot-typesafe-ai-chto-eto-za-model-bez-teksta-na-vyihode-i-pochemu-ona-deshevle-llm/)
- **Что взяли:** Концепция использования лёгких моделей без генерации текста для классификации запросов, маршрутизации (Router) и валидации аргументов инструментов.
- **Наша реализация:** Планируется как оптимизация для `detect_role` и валидации инструментов в `monitor.py`.

### 🆕 **BeeLlama.cpp** — Продвинутый форк llama.cpp
🔗 [ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp) и смежные оптимизированные форки
- **Что взяли:** Поддержка передовых оптимизаций инференса: спекулятивное декодирование (MTP/DFlash), TurboQuant и улучшенная работа с огромным контекстом на потребительском железе.
- **Наша реализация:** Концепция "Модульного ИИ-сервера", где ядро инференса отделено от логики агента. Это позволит в будущем бесшовно заменить стандартный `llama-server` на сборку BeeLlama для экстремального прироста скорости без переписывания кода агента.

### 🆕 **SSD Offloading & Memory Mapping (mmap)**
🔗 [SSD Offloading for LLM MoE Weights (Research)](https://arxiv.org/abs/2508.06978) / Native `llama.cpp` features
- **Что взяли:** Использование системного вызова `mmap` для потоковой подгрузки весов модели (особенно неактивных экспертов в MoE-архитектуре) с SSD/HDD в RAM по требованию, а не загрузки всего файла целиком.
- **Наша реализация:** Стратегия запуска моделей >10GB на системе с 32GB RAM. Мы полагаемся на ОС для умного управления памятью в фоновом режиме, предотвращая OOM-ошибки ценой небольшого, но приемлемого для фоновых задач снижения скорости.

### 🆕 **Low-Resource UX (Chunked Streaming / Batch Response)**
🔗 *(Внутренняя архитектурная находка проекта)*
- **Что взяли:** Понимание того, что при низкой скорости генерации на CPU (1-3 токена/сек) классический посимвольный стриминг создает у пользователя ложное ощущение зависания и излишне нагружает DOM браузера постоянной перерисовкой.
- **Наша реализация:** Внедрение режима "Тихой генерации": отображение понятного статусного индикатора ("🧠 Модель анализирует...") и мгновенный вывод готового текста целыми предложениями или логическими блоками по завершении генерации.

### 🆕 **BookWorm LLM (Локальное CPU-дообучение)**
🔗 *(Концепция на базе Hugging Face `transformers` + `peft` / native `llama.cpp` finetune)*
- **Что взяли:** Стратегия абсолютной приватности: локальный парсинг книг/документов, синтетическая генерация пар "вопрос-ответ" самой локальной моделью, и фоновое LoRA-обучение малых моделей (1.5B-3B) строго на CPU.
- **Наша реализация:** Учебный трек для создания предметно-ориентированных моделей (например, по корпоративной системе "Парус Предприятие") без передачи данных в облако, используя диск только как пассивное хранилище датасетов, а RAM — для активных вычислений.
