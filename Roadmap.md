# 🗺️ Дорожная карта AI Agent Hub (v3.0 Enhanced)
**Последнее обновление:** 2026-09-28  
**Версия:** 3.0 (Мульти-агентная архитектура, Web UI, продвинутый RAG и оптимизация ресурсов)

## 📊 Текущий статус
✅ **Модульное ядро (`agent_core`):** MCP-сервер разделён на логические модули (`agent_fs`, `agent_code`, `agent_memory`, `sandbox`).  
✅ **Мульти-агентная система:** 4 специализированные роли (Диспетчер, Инженер, Ревьюер, Библиотекарь) с динамической загрузкой промптов из папки `prompts/`.  
✅ **SandboxManager:** Двухуровневая защита (жёсткая граница `D:\Workspaces` + доверенные пути для чтения, например, `prompts/`).  
✅ **Web-интерфейс (AI Studio):** Современный UI на React/Vite/Tailwind с управлением проектами, экспортом/импортом данных и красивым рендерингом вызовов инструментов.  
✅ **Query Rewriter (`monitor.py`):** Умная маршрутизация запросов с определением роли агента до отправки в LLM.  
✅ **Ouroboros Loop (Фаза 1):** Автоматический перехват `stderr` и инъекция `similar_errors` перед запуском кода.

## 🌟 Долгосрочные идеи и Оптимизация ресурсов

- **Модульная архитектура ИИ-сервера (Plugin Architecture):** Полное отделение ядра инференса от логики агента (оркестратор, RAG, UI). Это позволит в будущем бесшовно заменить стандартный `llama-server` на оптимизированные форки (например, **BeeLlama.cpp** с поддержкой MTP/DFlash и TurboQuant) без переписывания кода самого агента.
- **SSD Offloading & Memory Mapping (`mmap`):** Стратегия запуска моделей >10GB на системе с 32GB RAM. Использование системного вызова `mmap` для потоковой подгрузки весов модели (особенно неактивных экспертов в MoE) с SSD/HDD в RAM по требованию, предотвращая OOM-ошибки ценой небольшого, но приемлемого для фоновых задач снижения скорости.
- **JEV (Joint Embedding-Vocabulary):** Использование сверхлёгких моделей без генерации текста для мгновенной классификации запросов (Router) и валидации аргументов инструментов перед отправкой в основную LLM.
- **Оптимизация префилл-кэша (Cache-Compact):** При сжатии длинного контекста сначала генерировать саммари на полном диалоге, и только затем заменять историю на `[System] + [Summary] + [Recent]`, чтобы не инвалидировать кэш `llama.cpp`.

## 🎓 Учебный трек: Локальное CPU-дообучение (BookWorm LLM) 🆕
**Тип:** Пет-проект для общего развития и MLOps-практики.  
**Приоритет:** 🟢 По желанию | **Статус:** 🟡 Концептуализация.  
**Цель:** Создание предметно-ориентированной модели (например, по системе "Парус Предприятие" или свежим книгам по Python) **строго локально, без облака**.  
**Этапы:**  
1. Локальный парсинг и очистка PDF/EPUB книг.  
2. Синтетическая генерация пар "вопрос-ответ" самой локальной моделью (формирование `dataset.jsonl`).  
3. Фоновое LoRA-обучение малых моделей (1.5B–3B) на CPU (используя `transformers`/`peft` или нативный `llama.cpp` finetune).  
4. Слияние адаптера с базовой моделью в GGUF и тестирование.  
*Примечание:* HDD используется только как пассивное хранилище датасетов и чекпоинтов, активные вычисления строго в 32GB RAM.

## ⚙️ Технические долги и уроки
1. **Форматирование JSON при экспорте:** Функция экспорта в AI Studio должна гарантированно удалять лишние пробелы в ключах (например, `"chats "` → `"chats"`), чтобы импорт не ломался молча.
2. **Создание `.memory`:** Папка `D:\Workspaces\.memory\` должна создаваться автоматически при инициализации `utils.py`, чтобы избежать ошибок `FileNotFoundError` в `agent_memory.py`.
3. **Позитивные промпты:** Избегать токсичных запретов ("ЗАПРЕЩЕНО", "НЕ ДЕЛАЙ"). LLM лучше понимают позитивные инструкции ("Используй только реальные инструменты MCP. Если планируешь, делай это обычным текстом").
